# リアルタイムの動画から店に人が何人いるかなどの混雑状況を調べることは可能？

**可能**。店側がカメラを置いて解析する用途なら、すでに商用サービスがある。店内全体を映さなくても、入口の入退店カウントや Wi-Fi / BLE の端末数から人数を推定する方法がある。一方で「今この店に何人いるか」を外から正確に知る手段としては弱く、Google マップの混雑表示のような相対的な推定が現実的な答えに近い。

## 短い答え

映像から人の形を見つけ、人数や通過数に落とす技術は実用段階にある。入口の頭上カメラなら来店・退店を数えやすく、店内のエリア人数やレジ待ちも取れる。ただし棚や人で隠れると漏れ、防犯カメラ1台で店全体の正確な在店人数を出すのは難しい。顔が識別できる映像は個人情報になり得るので、他人のカメラを覗く用途は対象外。

店内を全部映さなくても測れる。入口だけ数える方法と、スマホが出す Wi-Fi / Bluetooth の電波から端末数を数え、人数に換算する方法がある。端末数は人数そのものではなく、2台持ちは素朴に数えると2人になる。実務では「この店・この時間帯は端末何台で何人か」を学習してならす。個人の2台を1人に紐づける処理ではない。

## 何が測れるか

やりたいことに応じて、測り方が分かれる。

| 知りたいこと | よくある測り方 | 向き |
|---|---|---|
| 今、店に何人いるか | 入口の入店−退店、店内エリアの検出、または Wi-Fi / BLE 端末数の換算 | 入口頭上が強い。電波は店内全映し不要。死角・2台持ちでずれる |
| 今、レジが混んでいるか | レジ前エリアの人数・滞留 | ピンポイントなら実用的 |
| 今日何人来たか | 入口ラインの通過カウント | 小売でいちばんよく使う |
| どこに人が溜まっているか | ヒートマップ、ゾーン滞在 | レイアウト検証向き |
| 外から「混んでそう」 | Google マップの混雑時間・ライブ混雑 | 実人数ではなく相対値 |

日本でも Safie、TP-Link VIGI、OPTiM、Hikvision などが人数カウントを製品化している。Safie の人数カウントはカメラ1台あたり月額 5,500円（税込）のオプションで、通過人数・エリア立ち入り・滞留通知を出す。

## 映像から人数にする仕組み

だいたい次の三段で動く。

1. **人を見つける**  
   映像の各フレームから人（全身、または頭〜肩）を検出する。YOLO 系の物体検出がオープンソースでもよく使われる。密集すると「何人いるか」の密度マップ推定に切り替える研究もある。
2. **同一人物として追う**  
   フレームをまたいで ID を保つ（追跡）。入口をまたいだ入店・退店の判定や、同じ人を二重に数えないために使う。
3. **ルールで集計する**  
   入口に仮想ラインを引き、越えた向きで IN/OUT する（ラインクロス）。床に多角形を置いて、今その中に何ボックスあるかを数える（エリアカウント）。レジ前だけを切れば待ち列になる。

入口の頭上（真下向き、魚眼や 3D）の方が、斜めの防犯カメラより隠れにくい。OPTiM も、天井から真下に向けた専用カメラの方が精度が出やすい、と説明している。店内が広いと1台では足りず、複数カメラの視野が重なると同一人物を二重カウントしやすい。

「在店人数 = 入店 − 退店」は分かりやすいが、見逃しが積み上がってドリフトする。定期的にエリア内の実検出で補正するか、閉店時にゼロに戻す運用が現実的。

## 精度が落ちるところ

商用でも「常に正確な整数」ではなく、運営判断に足る数字、という位置づけが多い。

- **隠れ**: 棚、柱、カート、他の客の後ろ。横向きカメラで顕著。
- **密集**: 一人ずつ枠を取る検出は重なると漏れやすい。イベント会場のような密度では別系統の推定が必要。
- **遠さ・暗さ**: 人が小さく映る、逆光、夜間。
- **人以外**: マネキン、サイネージの人物、大きな荷物。逆に子どもやベビーカーは取りこぼしやすい。
- **スタッフ**: 制服検知などを足さない限り、客と店員は同じ「人」として入る。
- **死角**: カメラに映らない部屋・トイレ・倉庫は数えない。

研究側でも、頭上魚眼でも広い空間を1台でやると誤差が数十パーセントまで膨らみ、台数を増やして突き合わせると下がる、という報告がある。店の「混んでる／空いてる」やレジ補充の通知なら足りることが多く、「今ちょうど 37人」を監査する用途には向かない。

## カメラは店内全体を映す必要があるか

店内の「今映っている人数」を映像で足すなら、その通り死角は数えられない。ただし在店人数そのものは、店内を全部映さなくても取れる。

入口に頭上カメラを置き、入った数から出た数を引く方法が小売の定番。棚の裏は映らなくてよい。代わりに入口の見逃しが積み上がってずれるので、閉店でゼロに戻すか、どこかで実人数を見て補正する。レジ前だけ混雑を見たいなら、その区画だけ映せば足りる。

入口の赤外線ビームも同じ発想で、同時通過に弱い。

## Wi-Fi の端末数で測れるか

測れる。電波は棚の陰にも回り込みやすいので、カメラ全カバーより設置は楽なことが多い。数えているのは人ではなく、Wi-Fi や Bluetooth を出している機器。

やり方は大きく二つある。

| | 店の Wi-Fi に繋いだ端末 | 周囲を探す電波（プローブ等） |
|---|---|---|
| 拾う対象 | ゲスト Wi-Fi などに接続した機器 | 接続していなくてもスキャンしている機器 |
| 捕捉率 | 繋いだ人だけ。低いことが多い | 高いが、電波オフ・機内モードはゼロ |
| 識別 | そのネットにいるあいだは比較的安定 | MAC アドレスが頻繁にランダム化され、1台が何台にも見えやすい |
| 向き | 既存アクセスポイントの副産物 | 専用センサーで周囲の探索電波を拾う |

最近の iPhone / Android は、未接続の探索では MAC アドレスを次々変える。素朴に「ユニーク MAC 数 = 端末数」とすると水増しされる。Cisco Meraki などは、未接続かつランダム化されたアドレスを分析から落とす側に振っている。接続後はネットごとに固定のプライベートアドレスを使うことが多く、そのネットにいるあいだの重複は起きにくい。iOS 18 の Rotating 設定だと約2週間で変わる。

端末数から人数へは、式で割るより現場校正が普通。2026年3月、NTTドコモと東京大学は Wi-Fi / BLE センサーで iOS / Android 別の台数を取り、場所と時間帯ごとの「台数と人数の関係」を学習して人数に変換した。名古屋の d garden での実証は約 90%。日経の取材では、1人あたりのスマホ保有台数や通信状況の違いを加味すると説明されている。目標コストは AI カメラの 1/10。精度は端末保有率・電波環境・混雑度で変わる、と注記がある。

電波を出していない端末、端末を持たない人は拾えない。店の外の通行人の電波が漏れ込むこともあるので、受信強度で店内相当に切る。

## ホスト名で iPhone / Android だけ拾うか

店の Wi-Fi に繋がっている端末の名前から、`iPhone`・`Android`・`Phone` だけ残す、というやり方。ノートPC（`DESKTOP-`、`MacBook`）やプリンタ、スピーカーを落とせるので、生の接続台数より人に近い。だいたい、にはなるが、人数そのものにはならない。

前提が二つある。**繋がった端末しか見えない**ことと、**名前の文字列が機種を表すとは限らない**こと。ゲスト Wi-Fi に入らない客はゼロ。フリー Wi-Fi があっても接続率は低いことが多い。

iPhone は名前が残りやすい。初期名は「〜の iPhone」。プライベート Wi-Fi アドレスが Fixed（WPA2 以上のデフォルト）だと、DHCP のホスト名は個人名を消してただの `iPhone` になる、という報告がある。これでも `iPhone` フィルタには引っかかる。Rotating だとホスト名を出さないことがある。設定の名前を「太郎」だけに変えると、`iPhone` も `Phone` も無い。iPad は `iPad` なので `Phone` では落ちる。

Android はここが穴になる。Android 8 以降、公式に `net.hostname` を空にし、DHCP クライアントはホスト名を送らない。ルータの一覧が無名、というのが今の標準に近い。古い端末は `android-xxxxxxxx` を出す。一部メーカは `HUAWEI_P9`、`Xiaomi-15`、`AQUOS`、`Pixel-8` のような機種名を出す。`Android` も `Phone` も含まれない。日本のメイン利用 OS は iPhone 49.0%、Android 50.8%（MMD、2026年2月）なので、文字列だけで拾うと Android 側の半分近くが消える。

| 出やすい名前 | フィルタ `iPhone|Android|Phone` |
|---|---|
| `TaroのiPhone` / `iPhone` | 拾う |
| `android-a1b2c3` | 拾う（古い端末） |
| 名前なし（Android 8 以降の標準） | 落とす |
| `Pixel-8` / `AQUOS` / `Galaxy-S24` | 落とす |
| `MacBook-Pro` / `DESKTOP-XXXX` | 落とす（意図どおり） |
| 会社 iPhone と私用 iPhone | 2台拾う |

2台持ちは名前を見ても1人にならない。両方とも `iPhone` なら2人に見える。

名前より強いのは、DHCP のパラメータ要求リストなどから OS を推定する方法。ホスト名が空でも iOS / Android らしい、と分かることがある。NAC やフィンガープリント製品が使う類で、文字列一致より漏れは少ない。それでも「接続したスマホの台数」であり、店内の人数ではない。

ホスト名には「太郎の iPhone」のように個人名が残ることがある。人数の整数だけ残すより、識別に近い。残すならすぐ捨てるか、集計だけにする。

RFC 8117 は、公衆 Wi-Fi でホスト名が漏れる現状を有害としている。

## 2台持ちは2人になるか

素朴なユニーク端末カウントなら、その通り2人になる。デュアル SIM の1台は電波を出す本体が一つなので、だいたい1台。2台持ちは本体が二つある。

個人契約だけ見ると、ICT総研（2024年4月）では日常的に携帯・スマホを2台以上使う人は 10.4%（タブレットや法人名義は除外）。これは会社携帯＋私用の話ではない。ドコモ モバイル社会研究所（2024年1月）では、回線契約のある携帯電話を自分で2台以上持つ人は所有者の 14%。内訳はスマホ＋スマホ、スマホ＋タブレットが増えている。

会社携帯と私用の2台持ちは、別の調査を重ねる必要がある。「店の客の何%が会社＋私用を持ち歩いているか」という公式統計はない。近い数字は次のとおり。

| 何の数字か | 値 | 母数 |
|---|---|---|
| 社員のうち社用携帯を使っている | 31.4%（大企業 43.8%、中小 25.2%） | 20–69歳の正規雇用・経営者・公務員 1.5万人。MMD、2026年4月 |
| 会社員のうち会社支給スマホ | 19.2%（フィーチャーフォン込み支給は 23.4%） | MM総研、2023年 |
| スマホ契約に占める法人契約 | 13.5%（1680万件 / 1億2460万件） | MM総研、2026年3月末 |
| 社用携帯利用者のうち「私用と2台持ち歩くのが面倒」が不満1位 | 23.5% | MMD、2022年。2台持ちの人数そのものではない |

働く世代のスマホ保有はほぼ前提なので、社用を支給されている人の大半は私用も持っている。MMD の 31.4% は「支給されている／仕事で使っている」であり、昼休みに店へ両方持っていく比率ではない。休日は社用を家や会社に置く人も多い。逆に営業・外出職は平日どちらも持ち歩きやすい。MM総研（2026年6月）では、法人スマホを支給している職種は営業が 33.8% で最多。

だから Wi-Fi の係数は、平日のオフィス街ランチと休日の郊外スーパーでは別物になる。個人の2台持ち 10% だけで割ると、会社携帯が多い時間帯は足りない。

逆方向のズレもある。子どもや端末を置いてきた人は0、Apple Watch やイヤホン、タブレットは+1、店員のハンディやレジ周辺の機器も混ざる。

実務は「この2台は同一人物」と紐づけない。平均の端末/人でならす。

例: 客10人のうち1人が2台、9人が1台なら端末11、人数10。係数はおよそ 10/11。平日のビジネス街は2台持ちとノートPCが増え、休日の家族連れは端末を持たない子どもが増える。だから時間帯・エリア別に学習する。ドコモの方式も、個人の端末を名寄せせず、iOS 台数と Android 台数から人数へ変換する。

2台の軌跡がいつも同じ、と見て同一人物に畳む研究はあるが、同伴者と区別しにくく、追跡そのものが重い。混雑の相対値を取る用途では、係数で足りることが多い。客層が急に変わると係数が古くなる。入口カメラや実測で時々合わせ直すのが強い。

## 外から知りたい場合

自分の店ではなく、行きたい店の混雑を知る話だと、店内カメラには通常届かない。

Google マップの「混雑する時間帯」と「現在の混雑状況」は、ロケーション履歴をオンにしているユーザーの来訪を匿名集計した相対値で、実人数ではない。データが足りない店には出ない。差分プライバシーでノイズを足している、と Google は説明している。

店が自ら公開しているライブカメラを解析することは技術的には可能だが、顔が識別できる映像は個人情報になり得るし、利用規約や肖像の問題もある。他人の防犯カメラへ無断で入るのは論外。外から正確な在店人数を知る、という問いの実用解は、マップの混雑表示か、店が発表している待ち時間・整理券アプリの方になる。

## 法律とプライバシー（日本）

顔が識別できるカメラ映像は、個人情報保護委員会の整理では個人情報に該当することが多い。人数という統計だけを残し、顔の特徴を残さない **カウントデータ** は、総務省・経済産業省の『カメラ画像利活用ガイドブック ver3.0』（令和4年3月）では、単体では個人情報ではない、とされている。

ただし解析の途中の映像は個人情報として扱う必要がある。ガイドブックが想定する丁寧な運用は、利用目的の掲示、計測後の映像の速やかな削除、問い合わせ窓口の明示。店前の通行量のように屋外へ向けた撮影は、Safie も「防犯目的以外での映像活動はできません」と注記しており、テナントならデベロッパー確認が必要、としている。顔識別で同一人物を追い、来店履歴と結びつけるリピート分析は、人数カウントより一段重い取扱いになる。

ガイドブック自体は法令そのものではなく、商用のカメラ画像利活用で事業者が配慮すべき事項を整理した文書。防犯目的の監視そのものは対象外、と書かれている。Wi-Fi 側の機器識別子も、長期に同一人物へ紐づけられる形で残すと個人情報になり得る。ドコモの実証は匿名化・ハッシュ化して通信内容は取らない、と説明している。
